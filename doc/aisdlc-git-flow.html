aisdlc git flow

One shared workflow repository. base stays as it is. Each sprint gets its own branch created from base, and the whole team works on it. The next sprint starts again from base.

1. Branches across sprints

Workflow repository (tasks/, designs/, system/, repositories/, config/). Sprint branches are created by hand.

2. What each person does on the sprint branch

The same loop for every role. Each role's own plugin does the real work in the middle step.

3. Where the code lives

The workflow repository holds documents only. Application code stays in its own repositories.

4. Who enforces what

Rule How
Create the sprint branch from base (git switch -c S10 base) and have everyone check it out by hand
Keep base unchanged, except when repository details or config are added by hand
Move unreleased tickets to the next sprint with a cherry-pick by hand
/aisdlc:push pulls first, shows the branch and asks you to confirm it plugin
Merge conflicts are left to you; no force push plugin
Only tasks/, designs/, system/, repositories/, config/ are committed; commits read TICKET: summary plugin
Nothing is pushed to main plugin

Gap to be aware of: the plugin protects a branch named main. It does not know about base, so a push to base is not blocked yet. Until that is decided, keeping base untouched is a team habit, not a check.
