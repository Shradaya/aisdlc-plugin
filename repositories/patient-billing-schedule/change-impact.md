## 5. Behavior quirks to know before changing (all `[observed]`)

- Top-level `try/except` in `lambda_handler` swallows all errors and returns success; the only failure signal is Slack (needs `context`) plus logs.
- Duplicate processing is possible when `patient_id` and its `account` are both supplied (no de-duplication).
- `retry_on_write_conflict` silently returns `None` after the last conflict.
- SQS FIFO dedup id is random, so duplicate bot events are not suppressed.
- Bot send is now deferred to the end of the whole run (`flush_bot_events`, also in `finally`), after every patient commit; a failed send is recorded as `Fail` and not retried; queued events are lost if the Lambda dies before the flush `[inferred]`.
- Bot events with no active `manufacturer_accounts` record, or for in-office-only patients, are skipped silently apart from a `Skipped` status row (whose write needs an existing status document because of `upsert=False`).
- Live call tasks are archived (status change), not deleted, when a patient is deactivated at 730 days.
- `queue_bot_event` marks the patient as invoked even when the event is skipped, so no later schedule in the same run retries it.
- Reads inside the transaction are not bound to its session.
- Today is computed from the server clock, naive and local-time based.
